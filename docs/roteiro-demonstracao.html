Roteiro de demonstração

Nove passos, uns seis minutos. Cada um traz o que fazer e a finalidade — a frase que explica para que aquilo existe, que é o que se diz em voz alta enquanto a tela aparece.

Esta página é para quem apresenta

Quem vai usar não precisa dela. A explicação para o usuário final mora dentro da própria aplicação, em /como-usar — alcançável pelo item Como usar na barra, por um botão no pé da primeira tela e pelo painel vazio. É para lá que se manda alguém que perguntou “e como eu uso isso?”.

Antes de começar
docker compose up -d
Onde
http://localhost:5173
0 de 9 passos

A home

/

Cole uma URL longa e clique Encurtar. Aparecem o link curto, o QR Code e o botão de copiar. O botão Personalizar o link abre código escolhido, subdomínio, expiração e limite de cliques.

Cole o endereço sem o https:// — como se copia da barra do navegador. É aceito e completado no servidor, junto com os parâmetros de campanha, que atravessam intactos.

Rolando até o pé desta tela está o botão Como usar — vale apontar para ele, porque é para lá que a plateia volta sozinha depois.

Finalidade

Encurtar é a porta de entrada e não pede nada de ninguém. Quem só quer um link curto pega e vai embora.

Abra o link curto

/{codigo}

Numa aba nova. Ele redireciona para o destino. Volte e recarregue: o clique foi contado.

Finalidade

O endereço divulgado mora na raiz do domínio — curto de verdade. Cada acesso grava IP, navegador, origem e horário.

Criar conta

/criar-conta

Antes de acertar, digite a senha 12345678 para mostrar os dois motivos de recusa aparecendo juntos. Depois cadastre de verdade — cai direto no painel.

Finalidade

A conta é o que transforma um link solto num link acompanhado. Sem ela o link funciona; ele só não aparece em painel nenhum.

Um link com regras

/painel

Novo link → destino, código promo, expiração para daqui a alguns minutos e limite de 5 cliques únicos.

Finalidade

O link tem prazo e teto. Campanha que acaba, convite que não pode circular indefinidamente.

O painel

/painel/fichas

Mostre a soma de links e cliques no cabeçalho, a busca por código ou destino, o filtro Ativos/Inativos e o Ver como fichas, que abre o resumo completo: links, cliques totais, únicos e fora do ar.

Finalidade

É a mesa de trabalho de quem administra vários links ao mesmo tempo.

Trocar o destino

/links/{codigo}

Clique num link: cliques por dia, acessos recentes, QR Code e estado. Agora Editar link e troque o destino. Volte ao link curto e abra — sem limpar o cache, sem aba anônima — e ele vai para o endereço novo.

Baixe o QR Code antes de trocar e abra o PNG depois: o papel impresso na semana passada leva ao destino de agora. É a demonstração inteira num arquivo só.

Finalidade — o ponto central

O código divulgado nunca muda. Cartaz impresso, QR na embalagem, link no perfil: o destino por trás pode ser corrigido depois, sem reimprimir nada.

Por isso o desvio é temporário e vai com no-store. Um 301, que é o que muitos encurtadores devolvem, ficaria guardado no navegador de quem já clicou uma vez — e essa pessoa continuaria caindo no destino velho sem nem consultar o servidor.

Um segundo endereço

{apelido}.{dominio}

Editar link → preencha Subdomínio com promo. O mesmo link passa a responder também em promo.{dominio}, com o endereço de código valendo do mesmo jeito. Abra os dois: mesmo destino, e o clique cai na mesma contagem.

Depende de SHORTLINK_BASE_DOMAIN preenchido — vazio, o campo nem aparece na tela. Em desenvolvimento vale localhost:5173, que o navegador resolve sozinho. Em produção exige DNS e certificado curinga, e o passo a passo está na seção 10 do DEPLOY.md.

Finalidade

O endereço que se fala em voz alta. Um subdomínio não tem barra para soletrar e cabe num cartaz sem competir com o resto do texto — e continua sendo o mesmo link, com o mesmo destino trocável.

Tirar do ar

/links/{codigo}

Desativar e abrir o link curto: aparece uma página de bloqueio explicando que o link foi desativado.

Finalidade

Desligar é reversível, não revela para onde o link apontava e não conta o acesso. Vale igual para expirado e para limite atingido.

Duas contas

janela anônima

Crie outra conta numa janela anônima e cole o endereço do link da primeira (/links/promo). Resposta: “Este link pertence a outra conta.”

Finalidade

Cada painel enxerga só o que é dele. Não é filtro de tela — quem recusa é o servidor.

Se a plateia for técnica

:8000/api/health/ o que o orquestrador consulta para saber se a aplicação trabalha
terminal docker compose run --rm backend python manage.py test — 248 testes

E a API direto, se for o caso:

curl -X POST http://localhost:8000/api/urls/ \ -H "Content-Type: application/json" \ -d '{"original_url":"exemplo.com/promo?utm_source=cartaz","short_code":"promo"}'

Sem esquema na entrada e com https:// na saída, com o parâmetro de campanha intacto. Os cabeçalhos do desvio contam o resto da história:

curl -sI http://localhost:8000/promo

302 e cache-control: no-store — nunca 301.

Para não tropeçar

Teto de criação. São 20 links por hora sem conta e 120 com conta, contados por IP e por conta. Ensaiar muito antes pode bater o teto e devolver 429; para uma sessão longa, suba THROTTLE_LINK_ANON no .env e reinicie o backend.

O subdomínio é opcional e vem desligado. Sem SHORTLINK_BASE_DOMAIN no .env, o passo 7 não tem campo para preencher — e a tela esconde o campo de propósito, para ninguém escolher um endereço que o servidor não atende. Para ensaiar local, ponha localhost:5173 e reinicie o backend.

Nada está publicado ainda. Tudo aqui é local. Na VPS os endereços viram o seu domínio, e o passo a passo está no DEPLOY.md — falta apontar o domínio e emitir o certificado.
